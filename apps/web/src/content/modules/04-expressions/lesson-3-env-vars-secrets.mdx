Three ways to get a value into a workflow, for three different kinds of value.

## env

`env:` sets environment variables for the whole workflow, one job, or one step. Use it for values
that belong to this file.

<AnnotatedYaml
  file=".github/workflows/ci.yml"
  yaml={`env:
  NODE_ENV: test

jobs:
  build:
    runs-on: ubuntu-24.04
    env:
      LOG_LEVEL: debug
    steps:
      - run: echo "$NODE_ENV $LOG_LEVEL"
`}
  notes={[{ line: 10, text: 'In a run step they are ordinary environment variables, so the shell reads them with $NAME.' }]}
/>

## vars

Configuration variables are defined outside the file, at organisation, repository, or environment
level, and read with `vars.NAME`. Use them for non-sensitive settings that differ between
repositories or environments: a region, a server name, a feature flag.

They are **not** masked. GitHub's own warning is plain: variables render unmasked in build output, so
anything sensitive belongs in a secret.

## secrets

Secrets are encrypted before they reach GitHub, and a workflow can only read one you explicitly pass
it. Values are redacted from logs automatically.

Three caveats matter more than the mechanism:

- Redaction is **not guaranteed**. A secret that gets transformed — base64, a substring, JSON
  escaped — may not be recognised. Treat "it would be masked" as a safety net, not a design.
- The runner can only redact secrets used in the **current job**.
- Secrets are not available to workflows triggered from forks, which is deliberate.

## Choosing between them

| Value | Where it goes |
| --- | --- |
| Something this file needs, no secrecy | `env` |
| Shared, non-sensitive, varies by repository or environment | `vars` |
| A credential | `secrets`, granted the fewest permissions possible |

The security module goes further: preferring short-lived tokens over long-lived ones, and using OIDC
so no cloud key is stored at all. For now, the habit is smaller — if leaking it would matter, it is a
secret, and the fact that logs are usually scrubbed is not a reason to be careless.
