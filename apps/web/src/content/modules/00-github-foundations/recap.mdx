- A repository holds the project and its history; branches keep unfinished work away from `main`.
- A pull request turns commits into a conversation, and its Checks tab is where your pipeline reports.
- A fork is a separate repository you own, so a pull request from one runs code that is not yours.
- Rulesets make checks binding: require a pull request, require status checks, block force pushes.
- Strict status checks require the branch to be up to date before merging; loose ones do not.
